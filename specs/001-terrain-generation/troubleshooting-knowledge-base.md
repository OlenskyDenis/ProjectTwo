<a name="bug-001"></a>
### 1. BUG-001: Відкриті темні щілини та "загортання" рядків сітки (Row Wrapping)

* **Симптоми**: При віддаленні камери та переході чанків на вищі рівні LOD (LOD 1, 2...) з'являлися темні смуги та розірвані трикутники, що перетинали чанк по діагоналі.
* **Першопричина**:
  1. Роздільна здатність задавалася як $N = 120$ вершин. Кількість сегментів становила $120 - 1 = 119$ (просте непарне число, неділиме на кроки LOD 2, 4, 6).
  2. Цикл тріангуляції використовував сирі координати `x += lodStep`. Через неділимість останній елемент рядка ($x = 118$) помилково вважався внутрішнім і з'єднувався з вершиною $x = 0$ наступного рядка (`vertexIndex + 1`), зшиваючи протилежні краї чанка.
* **Як вирішено**:
  * **Формула точок**: Для $N$ сегментів генерується $N + 1$ вершин висотної карти (наприклад, 121 вершина для 120 сегментів).
  * **Індексний цикл**: Цикли замінено на `for (int xIndex = 0; xIndex < verticesPerLineX; xIndex++)`. Умова додавання трикутника: `xIndex < verticesPerLineX - 1 && zIndex < verticesPerLineZ - 1`, що на 100% унеможливлює перескакування між рядками.
  * **Smart Snapping**: У `TerrainDataConfig` та `TerrainDataConfigEditor` додано автоматичну прив'язку роздільної здатності до чисел, кратних **12** (24, 48, 72, 96, 120, 240).
* **Файли**: `TerrainMeshBuilder.cs`, `TerrainDataConfig.cs`, `TerrainDataConfigEditor.cs`.

<a name="bug-002"></a>
### 2. BUG-002: Розрив висот по осі Z через дзеркальну орієнтацію (Z-Axis Inversion)

* **Симптоми**: По осі X чанки з'єднувалися плавно, а по осі Z рельєф мав різкі сходинки та перепади на кожному стику.
* **Першопричина**:
  * Локальна позиція вершини розраховувалася як `posZ = halfChunkSize - percentZ * chunkSize` (інвертований напрямок від $+Z$ до $-Z$).
  * Світова координата чанка `chunkCoord.Z` зростала в прямому напрямку ($+Z$).
  * Через це північний край чанка `(0, 0)` зустрічався з південним краєм чанка `(0, 1)`, але вони брали значення з протилежних кінців функції шуму з розривом у 2 повні розміри чанка.
* **Як вирішено**:
  1. Синхронізовано розрахунок позиції Z: `posZ = -halfChunkSize + percentZ * chunkSize`.
  2. Оновлено порядок тріангуляції на прямий обхід за годинниковою стрілкою: `(current, top, topRight)` та `(current, topRight, right)`.
  3. Виправлено розрахунок `localZ` у методі `ITerrainProvider.GetHeight`.
  4. Додано автоматичний NUnit тест, що одночасно валідує стики вздовж осей X та Z.
* **Файли**: `TerrainMeshBuilder.cs`, `TerrainGenerator.cs`, `TerrainMeshBuilderTests.cs`.

<a name="bug-003"></a>
### 3. BUG-003: Тонка лінія світлотіні на стику чанків (Lighting Normal Seam)

* **Симптоми**: Геометрія стикувалася впритул без дірок, але візуально залишалася помітною тонка хрестоподібна лінія затінення вздовж меж чанків.
* **Першопричина**:
  * Використання стандартного `mesh.RecalculateNormals()` розраховувало вектор нормалі вершини лише на основі трикутників усередині одного чанка.
  * Крайня вершина чанка А не мала трикутників із чанка Б, тому її нормаль відхилялася всередину. При розрахунку освітлення виникав різкий перепад яскравості на межі.
* **Як вирішено**:
  * Реалізовано аналітичний розрахунок нормалей за градієнтом висотної карти (метод центральних різниць `CalculateSmoothNormal`):
    $$\text{normal} = \text{normalize}\left(\frac{h_L - h_R}{\Delta X}, 2.0, \frac{h_D - h_U}{\Delta Z}\right)$$
  * Вектори нормалей на межах чанків стали абсолютно ідентичними, лінія затінення зникла.
* **Файли**: `TerrainMeshBuilder.cs`.

<a name="bug-004"></a>
### 4. BUG-004: Чорні крапки та мікрощілини в далині (LOD T-Junction Cracks)

* **Симптоми**: У далині, де чанки переходили на інші рівні LOD, на стиках з'являлися чорні крапки або мерехтливі пікселі.
* **Першопричина**:
  * Коли сусідні чанки мають різну роздільну здатність (наприклад, LOD 0 має 120 сегментів, а LOD 1 — 60 сегментів), прямий відрізок LOD 1 утворює плоску хорду під криволінійною дугою пагорба LOD 0.
  * Між ними виникали мікроскопічні Т-подібні щілини (T-Junctions), крізь які просвічував чорний колір порожнечі під сценою.
* **Як вирішено**:
  * Додано технологію **Terrain Mesh Skirts** (захисні вертикальні спідниці по 4 зовнішніх краях кожного чанка, витягнуті вниз на `skirtDepth`).
  * Спідниця перекриває будь-які розбіжності хорд різних рівнів LOD під поверхнею землі, на 100% усуваючи просвічування.
* **Файли**: `TerrainMeshBuilder.cs`.

<a name="bug-005"></a>
### 5. BUG-005: Помилка Input System у лічильнику FPS (InvalidOperationException)

* **Симптоми**:
  `InvalidOperationException: You are trying to read Input using the UnityEngine.Input class, but you have switched active Input handling to Input System package in Player Settings.`
* **Першопричина**:
  * У проекті Unity 6 активовано новий пакет **Unity Input System** (`com.unity.inputsystem`), за якого звернення до старого статичного класу `UnityEngine.Input.GetKeyDown` заборонені рушієм.
* **Як вирішено**:
  * Клавішу перемикання `F3` переведено на новий Input System API:
    ```csharp
    Keyboard keyboard = Keyboard.current;
    if (keyboard != null && keyboard.f3Key.wasPressedThisFrame)
    {
        _isVisible = !_isVisible;
    }
    ```
* **Файли**: `FPSCounter.cs`.

<a name="bug-006"></a>
### 6. BUG-006: Попередження Unity про зміну асетів у immutable пакетах

* **Симптоми**:
  `The following asset(s) located in immutable packages were unexpectedly altered: Packages/com.unity.render-pipelines.core/.../RuntimeDebugWindow_PanelSettings.asset`
* **Першопричина**:
  * Внутрішній модуль налагодження SRP (`DebugManager` / `RuntimeDebugWindow`) під час виконання тестів тимчасово модифікує власний UI-асет налаштувань у кеші пакетів.
* **Як вирішено / Трактування**:
  * Не є помилкою користувацького коду. Попередження є внутрішньою особливістю Unity Package Manager і безпечно скидається автоматично або очищується в консолі кнопкою `Clear`.
