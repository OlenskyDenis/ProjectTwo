<a name="bug-001"></a>
### 1. BUG-001: Відкриті темні щілини та "загортання" рядків сітки (Row Wrapping)

* **Симптоми**: При віддаленні камери та переході чанків на вищі рівні LOD (LOD 1, 2...) з'являлися темні смуги та розірвані трикутники, що перетинали чанк по діагоналі.
* **Першопричина**:
  1. Роздільна здатність задавалася як $N = 120$ вершин. Кількість сегментів становила $120 - 1 = 119$ (просте непарне число, неділиме на кроки LOD 2, 4, 6).
  2. Цикл тріангуляції використовував сирі координати `x += lodStep`. Через неділимість останній елемент рядка ($x = 118$) помилково вважався внутрішнім і з'єднувався з вершиною $x = 0$ наступного рядка (`vertexIndex + 1`), зшиваючи протилежні краї чанка.
* **Як вирішено**:
  * **Формула точок**: Для $N$ сегментів генерується $N + 1$ вершин висотної карти (наприклад, 121 вершина для 120 сегментів).
  * **Індексний цикл**: Цикли замінено на `for (int xIndex = 0; xIndex < verticesPerLineX; xIndex++)`. Умова додавання трикутника: `xIndex < verticesPerLineX - 1 && zIndex < verticesPerLineZ - 1`, що на 100% унеможливлює перескакування між рядками.
  * **Smart Snapping**: У `TerrainDataConfig` та `TerrainDataConfigEditor` додано автоматичну прив'язку роздільної здатності до чисел, кратних **12** (24, 48, 72, 96, 120, 240).
* **Файли**: `TerrainMeshBuilder.cs`, `TerrainDataConfig.cs`, `TerrainDataConfigEditor.cs`.

<a name="bug-002"></a>
### 2. BUG-002: Розрив висот по осі Z через дзеркальну орієнтацію (Z-Axis Inversion)

* **Симптоми**: По осі X чанки з'єднувалися плавно, а по осі Z рельєф мав різкі сходинки та перепади на кожному стику.
* **Першопричина**:
  * Локальна позиція вершини розраховувалася як `posZ = halfChunkSize - percentZ * chunkSize` (інвертований напрямок від $+Z$ до $-Z$).
  * Світова координата чанка `chunkCoord.Z` зростала в прямому напрямку ($+Z$).
  * Через це північний край чанка `(0, 0)` зустрічався з південним краєм чанка `(0, 1)`, але вони брали значення з протилежних кінців функції шуму з розривом у 2 повні розміри чанка.
* **Як вирішено**:
  1. Синхронізовано розрахунок позиції Z: `posZ = -halfChunkSize + percentZ * chunkSize`.
  2. Оновлено порядок тріангуляції на прямий обхід за годинниковою стрілкою: `(current, top, topRight)` та `(current, topRight, right)`.
  3. Виправлено розрахунок `localZ` у методі `ITerrainProvider.GetHeight`.
  4. Додано автоматичний NUnit тест, що одночасно валідує стики вздовж осей X та Z.
* **Файли**: `TerrainMeshBuilder.cs`, `TerrainGenerator.cs`, `TerrainMeshBuilderTests.cs`.

<a name="bug-003"></a>
### 3. BUG-003: Тонка лінія світлотіні на стику чанків (Lighting Normal Seam)

* **Симптоми**: Геометрія стикувалася впритул без дірок, але візуально залишалася помітною тонка хрестоподібна лінія затінення вздовж меж чанків.
* **Першопричина**:
  * Використання стандартного `mesh.RecalculateNormals()` розраховувало вектор нормалі вершини лише на основі трикутників усередині одного чанка.
  * Крайня вершина чанка А не мала трикутників із чанка Б, тому її нормаль відхилялася всередину. При розрахунку освітлення виникав різкий перепад яскравості на межі.
* **Як вирішено**:
  * Реалізовано аналітичний розрахунок нормалей за градієнтом висотної карти (метод центральних різниць `CalculateSmoothNormal`):
    $$\text{normal} = \text{normalize}\left(\frac{h_L - h_R}{\Delta X}, 2.0, \frac{h_D - h_U}{\Delta Z}\right)$$
  * Вектори нормалей на межах чанків стали абсолютно ідентичними, лінія затінення зникла.
* **Файли**: `TerrainMeshBuilder.cs`.

<a name="bug-004"></a>
### 4. BUG-004: Чорні крапки та мікрощілини в далині (LOD T-Junction Cracks)

* **Симптоми**: У далині, де чанки переходили на інші рівні LOD, на стиках з'являлися чорні крапки або мерехтливі пікселі.
* **Першопричина**:
  * Коли сусідні чанки мають різну роздільну здатність (наприклад, LOD 0 має 120 сегментів, а LOD 1 — 60 сегментів), прямий відрізок LOD 1 утворює плоску хорду під криволінійною дугою пагорба LOD 0.
  * Між ними виникали мікроскопічні Т-подібні щілини (T-Junctions), крізь які просвічував чорний колір порожнечі під сценою.
* **Як вирішено**:
  * Додано технологію **Terrain Mesh Skirts** (захисні вертикальні спідниці по 4 зовнішніх краях кожного чанка, витягнуті вниз на `skirtDepth`).
  * Спідниця перекриває будь-які розбіжності хорд різних рівнів LOD під поверхнею землі, на 100% усуваючи просвічування.
* **Файли**: `TerrainMeshBuilder.cs`.

<a name="bug-005"></a>
### 5. BUG-005: Помилка Input System у лічильнику FPS (InvalidOperationException)

* **Симптоми**:
  `InvalidOperationException: You are trying to read Input using the UnityEngine.Input class, but you have switched active Input handling to Input System package in Player Settings.`
* **Першопричина**:
  * У проекті Unity 6 активовано новий пакет **Unity Input System** (`com.unity.inputsystem`), за якого звернення до старого статичного класу `UnityEngine.Input.GetKeyDown` заборонені рушієм.
* **Як вирішено**:
  * Клавішу перемикання `F3` переведено на новий Input System API:
    ```csharp
    Keyboard keyboard = Keyboard.current;
    if (keyboard != null && keyboard.f3Key.wasPressedThisFrame)
    {
        _isVisible = !_isVisible;
    }
    ```
* **Файли**: `FPSCounter.cs`.

### 6. BUG-006: Попередження Unity про зміну асетів у immutable пакетах

* **Симптоми**:
  `The following asset(s) located in immutable packages were unexpectedly altered: Packages/com.unity.render-pipelines.core/.../RuntimeDebugWindow_PanelSettings.asset`
* **Першопричина**:
  * Внутрішній модуль налагодження SRP (`DebugManager` / `RuntimeDebugWindow`) під час виконання тестів тимчасово модифікує власний UI-асет налаштувань у кеші пакетів.
* **Як вирішено / Трактування**:
  * Не є помилкою користувацького коду. Попередження є внутрішньою особливістю Unity Package Manager і безпечно скидається автоматично або очищується в консолі кнопкою `Clear`.

<a name="bug-007"></a>
### 7. BUG-007: PhysX попередження про великі трикутники > 500 юнітів та подвійне масштабування висоти

* **Симптоми**:
  `Detected one or more triangles where the distance between any 2 vertices is greater than 500 units. The resulting Triangle Mesh can impact simulation and query stability. Source mesh name: TerrainCollisionMesh / TerrainChunkMesh`
* **Першопричина (5 Whys Root-Cause Analysis)**:
  1. **Подвійне масштабування висоти**: `ProceduralTerrainShaper.CalculateElevation` розраховував світову висоту (наприклад, $75\text{м}$) і записував її у `HeightMap`. Потім `TerrainMeshBuilder` вважав ці дані нормалізованими $[0..1]$ і повторно множив їх на `HeightMultiplier`. В результаті висота гір піднімалася до $75 \times 75 = 5625\text{ метрів}$, утворюючи вертикальні голки з перепадами $800+\text{м}$ на одному трикутнику.
  2. **Єдиний меш для графіки та фізики**: `TerrainChunkView` передавав у `MeshCollider` візуальний меш із вертикальними декоративними спідницями (skirt walls), які при високих горах створювали великі підземні трикутники.
  3. **Запікання колізій у режимі Edit Mode та на далеких LOD**: `MeshCollider` намагався згенерувати фізичну сітку колізій навіть у режимі редагування сцени або для спрощених далеких LOD.
* **Як вирішено**:
  1. **Нормалізація буфера висот**: `ProceduralTerrainShaper.GenerateHeightMap` тепер записує у `HeightMap` строго нормалізовані значення $[0..1]$ (ділячи розраховану висоту на `HeightMultiplier`), а `TerrainMeshBuilder` множить на висоту рівно один раз.
  2. **Повне розділення Visual та Collision мешів**:
     * `TerrainVisualMesh` будується зі спідницями (`includeSkirt: true`) для безшовного рендерингу.
     * `TerrainCollisionMesh` будується без спідниць (`includeSkirt: false`) як чиста поверхнева сітка з кроком $2\text{–}5\text{м}$.
  3. **Обмеження запікання колізій**: `MeshCollider` активується виключно у `Play Mode` і лише для детального `LOD 0`.
  4. **Автоматичний юніт-тест**: Додано тест `GenerateTerrainMesh_CollisionMesh_HasNoEdgesLongerThan500Units_EvenWithExtremeMountains`, що перевіряє довжини ребер при екстремальній висоті $800\text{м}$.
* **Файли**: `ProceduralTerrainShaper.cs`, `TerrainMeshBuilder.cs`, `TerrainChunkView.cs`, `TerrainMeshBuilderTests.cs`.

<a name="arch-008"></a>
### 8. ARCH-008: Захист від зависань та витоків пам'яті через CancellationTokenSource

* **Симптоми**: Зависання Unity та накопичення нескасованих фонових задач `Task.Run` при швидкому перетягуванні повзунків конфігурації у Scene View.
* **Першопричина**: При зміні налаштувань кожний кадр запускав нову задачу генерації чанка у ThreadPool, не зупиняючи попередні обчислення, що призводило до забивання пулу потоків застарілими даними та накладання результатів.
* **Як вирішено**:
  * Впроваджено кооперативне скасування через `CancellationTokenSource`: при початку нової генерації або перемиканні LOD старий токен скасовується:
    ```csharp
    if (_generationCts != null)
    {
        _generationCts.Cancel();
        _generationCts.Dispose();
    }
    _generationCts = new CancellationTokenSource();
    ```
  * У фоновій задачі додано перевірки `if (token.IsCancellationRequested) return;`.
  * У режимі редагування (Edit Mode) додано обов'язкове явне очищення старих прев'ю-об'єктів через `DestroyImmediate`.
* **Файли**: `TerrainGenerator.cs`.

<a name="ux-009"></a>
### 9. UX-009: 3-вкладковий редизайн інспектора та система багаторівневого скидання налаштувань

* **Симптоми**: Інспектор `TerrainConfig` був перевантажений математичними термінами (`Lacunarity`, `Octaves`, `Persistence`), містив 10 вкладених вертикальних меню, і не мав можливості швидко повернути параметри до робочого стану.
* **Як вирішено**:
  1. **3-вкладкова архітектура (Navigation Tabs)**:
     * **`🌟 Швидкий режим`**: 5 готових світів в 1 клік, кнопка `🎲 New Seed` та 5 зрозумілих повзунків (висота в метрах, масштаб простору, скелястість, океан, острів).
     * **`🎨 Біоми й Кольори`**: 5 готових палітр (Літо, Осінь, Зима, Пустеля, Тропіки) + інтерактивна кольорова смуга градієнта висот ($0.0 \to 1.0$).
     * **`🛠️ Pro / Детально`**: Повний інженерний доступ до всіх фракталів, LOD-рівнів та кривих.
  2. **Система багаторівневого скидання (Reset to Defaults)**:
     * Додано метод `ResetToDefaults()` у `TerrainDataConfig.cs`.
     * Додано глобальну кнопку **Factory Reset** з вікном підтвердження та підтримкою `Undo (Ctrl+Z)`.
     * Додано локальні кнопки скидання для кожної секції у Pro-режимі.
* **Файли**: `TerrainDataConfig.cs`, `TerrainDataConfigEditor.cs`, `TerrainRegion.cs`.

<a name="bug-010"></a>
### 10. BUG-010: Засмічення сцени в EditMode та ризик прихованого витоку пам'яті (Hierarchy Observability vs Stealth Masking)

* **Симптоми**: При зупинці гри або редагуванні сцени в ієрархії під `Terrain_Manager` накопичувалися об'єкти `TerrainChunk`, позначаючи сцену як збережену з брудом (`SampleScene*`). Спроба приховати їх через `HideFlags.HideAndDontSave` створила ризик невидимого витоку пам'яті (Leak by Stealth) та порушила прозорість для QA.
* **Першопричина**:
  1. `TerrainGenerator` з атрибутом `[ExecuteAlways]` повторно ініціалізував пул об'єктів `ChunkObjectPool` при переході в EditMode.
  2. `HideFlags.DontSave` не приховує об'єктів з Hierarchy, а `HideAndDontSave` маскує їх від QA та блокує вивантаження з пам'яті.
* **Як вирішено**:
  * **Жорстке блокування в EditMode**: У конструкторі `ChunkObjectPool` встановлено `int capacity = Application.isPlaying ? initialCapacity : 0;`. Поза грою пул не створює жодного об'єкта.
  * **Прозорий `DontSave`**: Залишено `HideFlags.DontSave`, що забезпечує повну видимість чанків у Hierarchy під час PlayMode (Observability) і водночас гарантує відсутність серіалізації на диск у файл `.unity`.
  * **Гарантований Teardown**: У `TerrainGenerator.cs` додано обов'язкове очищення `ClearAllChunks()` та `_chunkPool.Clear()` у методі `OnDisable()`, що фізично знищує всі створені об'єкти при зупинці гри.
* **Файли**: `ChunkObjectPool.cs`, `TerrainGenerator.cs`, `DomainModelTests.cs`.

<a name="bug-011"></a>
### 11. BUG-011: Рожевий колір водної гладі річки (Error Shader) та діагональні розриви геометрії у небо

* **Симптоми**: Річкова сітка рендерилася яскраво-малиновим кольором помилки (Magenta), а водна стрічка під крутим кутом стирчала вгору від русла.
* **Першопричина**:
  1. `TerrainChunkView.cs` шукав шейдер `"ProjectTwo/Terrain/WaterSimple"`, який вимагав `UniversalPipeline`. При відсутності URP-пакета або конфігурації матеріал не ініціалізувався і падав у рожевий `Error Shader`.
  2. У `HydrologyService.cs` метод `SampleElevation` повертав нормалізоване значення $[0, 1]$ замість світової висоти в метрах (`normalized * noise.HeightMultiplier`), через що витоки річок та проміжні точки сплайна мали стрибки висоти від 65м до 0.6м.
* **Як вирішено**:
  * **Каскадний фолбек шейдерів**: У `TerrainChunkView.cs` додано послідовний пошук шейдерів (`WaterSimple` $\to$ `Universal Render Pipeline/Lit` $\to$ `Universal Render Pipeline/Simple Lit` $\to$ `Standard` $\to$ `Sprites/Default` $\to$ `Unlit/Color`) з обов'язковим призначенням водного кольору через `_BaseColor`, `_Color` та `.color`.
  * **Синхронізація висот**: `SampleElevation` помножено на `noise.HeightMultiplier`, а резервні витоки річок прив'язано до реальної поверхні ландшафту.
* **Файли**: `TerrainChunkView.cs`, `HydrologyService.cs`, `RiverMeshBuilder.cs`, `RiverMeshBuilderTests.cs`.

### 12. BUG-012: Зависання інспектора ("Hold on...") при перемиканні вкладок конфігуратора

### 21. BUG-021: Відірвані фрагменти водної стрічки в небі через незавершені трасування та відсутність зворотного очищення графа (Backward Reachability Pruning)

* **Симптоми**: У гірських районах на висоті з'являлися поодинокі сині трапеції/прямокутники водної сітки без витоку та гирла, що зависали у повітрі або на хребтах.
* **Першопричина (5 Whys Analysis)**:
  1. **Незавершені трасування річок**: Коли випадково згенерований витік річки потрапляв на плато або локальну западину, градієнт висоти ставав близьким до нуля ($\le 0.005$). Трасувальник зупинявся після 1–2 кроків (25–50 метрів).
  2. **Фіктивне очищення глухих кутів**: Попередній метод `PruneDeadEndOrphanSegments` перевіряв лише довжину сегмента `Length < 0.01f`, але не перевіряв топологічну зв'язність графа. Обірваний ланцюжок з 1–2 сегментів залишався у глобальному графі `RiverGraph`.
  3. **Відсутність обов'язкового зв'язування з приймачем стоку (Sinks)**: Сегменти потрапляли в генератор мешів `RiverMeshBuilder`, який рендерив ці поодинокі відрізки як ізольовані водяні полігони.
  4. **Односторонній рендеринг у шейдері**: Водний шейдер `WaterSimple.shader` мав `Cull Back`, через що при перегляді збоку чи знизу стрічка частково зникала, підсилюючи враження обірваних клаптів.
* **Як вирішено**:
  1. **Алгоритм зворотного обходу графа (Backward Reachability BFS)**: Впроваджено топологічний аналіз: від усіх валідних кінцевих приймачів води (`OceanMouth`, `DeltaMouth`, `LakeInflow`, а також берегів на рівні моря) запускається зворотний BFS-пошук по орієнтованому графу сегментів. Усі відрізки, що не ведуть у море чи озеро, безповоротно видаляються з графа.
  2. **Двосторонній рендеринг води**: У `WaterSimple.shader` увімкнено `Cull Off`, усуваючи зникнення водної гладі при довільних ракурсах камери.
  3. **Точкове притягування висот**: Кожна вершина сітки річки на кожному кроці розбиття $t$ розраховує світову висоту $Y = \text{CalculateElevation}(X, Z) + 0.15\text{м}$ через авторитарний пайплайн рельєфу.
* **Файли**: `HydrologyService.cs`, `RiverMeshBuilder.cs`, `WaterSimple.shader`, `AdvancedHydrologyTests.cs`.

### 22. BUG-022: Сходинковий/лускатий вигляд водної стрічки (Shingled Slicing) через незшиті сегменти на стиках вузлів

* **Симптоми**: При звивистому або крутому спуску річка виглядала не як суцільна гладка водна стрічка, а як набір повернутих нез'єднаних прямокутних пластин («луска» або нарізаний хліб) із проміжками між сусідніми відрізками.
* **Першопричина (5 Whys Analysis)**:
  1. **Ізольована генерація сегментів**: Кожен сегмент річки у циклі `for (s = 0; s < segments.Count)` генерував власний ізольований набір вершин і трикутників від $t=0$ до $t=1$.
  2. **Розбіжність тангенсів на стиках**: На вузлі $N_k$, де сходяться сегмент $S_{i}$ та $S_{i+1}$, вектор напрямку кінця першого сегмента і початку другого сегмента відрізнялися через поворот русла.
  3. **Відсутність зшивання (Welding)**: Вершини $(left, right)$ для $S_i(t=1)$ та $S_{i+1}(t=0)$ генерувалися незалежно з різними бінормалями та не зв'язувалися трикутниками, утворюючи розрив та перекриття прямокутників під кутом.
* **Як вирішено**:
  1. **Усереднення тангенсів вузлів (Miter-Averaged Node Frames)**: Перед генерацією сітки для кожного вузла графа розраховується згладжений середній тангенс $\vec{T}_{\text{avg}} = \text{normalize}(\vec{T}_{\text{in}} + \vec{T}_{\text{out}})$ та єдиний ортогональний базис $(\vec{n}, \vec{b})$.
  2. **Топологічне зшивання кілець вершин (Vertex Ring Welding)**: Початкове кільце вершин сегмента $S_{i+1}$ повторно використовує кінцеві вершини сегмента $S_i$, а трикутники зв'язують усю гілку в єдину безшовну неперервну стрічку без жодного розриву чи накладання.
* **Файли**: `RiverMeshBuilder.cs`, `AdvancedHydrologyTests.cs`.

### 23. BUG-023: Тупі обрізані кінці річок та шаховий муар текстури (Blunt Terminus & UV Moire)

* **Симптоми**:
  1. На початку (витік) та наприкінці (гирло або безстічний басейн) водна стрічка обривалася рівним тупим прямокутним зрізом, немов відрізаний шланг.
  2. На окремих ділянках водної поверхні з'являвся шаховий або зигзагоподібний муар через розрив текстурних UV-координат.
* **Першопричина (5 Whys Analysis)**:
  1. **Відсутність звуження витоків/гирл**: Русло генерувало постійну або лінійну ширину $\ge 1.5$м від першого до останнього метра, не враховуючи, що в природі витік б'є з джерела (точка), а на суші без океану вода просочується в алювій (звуження до нуля).
  2. **Індексна прив'язка UV**: Розрахунок текстурної координати $V$ базувався на локальному індексі сегмента в масиві чанка `s * subdivisions + step`, а не на монотонній кумулятивній світовій відстані вздовж сплайна, що створювало стрибки UV при зшиванні вузлів.
* **Як вирішено**:
  1. **Природне конусне згладжування (Spring & Terminal Infiltration Tapering)**:
     - Для витоків без вхідних річок ширина плавно зростає від $0.1$м до повної за допомогою `Mathf.SmoothStep(0.08f, 1f, t * 4f)`.
     - Для кінцевих точок без океану ширина плавно сходить нанівець до $0.1$м через `Mathf.SmoothStep(1f, 0.08f, (t - 0.75f) * 4f)`, безшовно ховаючись у ґрунті.
  2. **Кумулятивна світова дистанція UV**: Координата $V$ тепер розраховується строго монотонно від фізичної довжини сплайна (`currentDist * 0.05f`), усуваючи будь-який муар.
* **Файли**: `RiverMeshBuilder.cs`, `AdvancedHydrologyTests.cs`.
